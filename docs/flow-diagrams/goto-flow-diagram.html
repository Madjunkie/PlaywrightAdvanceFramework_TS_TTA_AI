TTACart · LoginPage

await this.goto(LoginPage.PATH);
how it flows internally

One line inside open() passes through the spec, the page object, the base class and the config before it becomes an HTTP request.

test page object base class config network
The path stays a plain string the whole way down. baseURL is only applied inside Playwright — the page object never knows the host.

The flow

1
test
The spec calls open() and waits
await loginPage.open();
The await makes everything below sequential. Without it, the next line would race the page load.
2
page object
open() logs intent, then delegates
this.log.info("Open login page");
await this.goto(LoginPage.PATH);
The log fires before navigation, so if it throws you still have a breadcrumb. open() takes no arguments — the route is fixed in the class.
3
page object
PATH is read off the class, not the instance
static readonly PATH = '/playwright/ttacart/';
static means it exists before any object is built. It is relative — no host, no protocol. Same pattern in every page object.
4
base class
goto() is inherited from BasePage
protected async goto(relativePath: string): Promise<void>
protected is the point: subclasses may call it, tests cannot. A spec has to go through open(), so the route lives in one place.
5
base class
The path is handed to Playwright
await this.page.goto(relativePath);
It uses this.page directly, not this.el — navigation skips the element wrapper entirely.
6
config
Playwright joins the path with baseURL
new URL('/playwright/ttacart/', baseURL)
This is the only place the host gets added. See the panels below.
7
network
The browser requests the page and waits for load
GET https://app.thetestingacademy.com/playwright/ttacart/
200 OK   ->   <title>TTACart - Login</title>
Waits for the load event by default, with a 30 second navigation timeout.
8
base class
One extra safety wait
await this.page.waitForLoadState('domcontentloaded');
load already fires after DOMContentLoaded, so this normally returns instantly. Insurance, not a real wait — it does not wait for networkidle.
9
test
Control comes back to the spec
await loginPage.loginAs("standard_user", "tta_secre");
Only now is the login form guaranteed to be in the DOM.

Path resolution

Joining the two halves

PATH '/playwright/ttacart/' baseURL 'https://app.thetestingacademy.com' ------------------------------------------------ result 'https://app.thetestingacademy.com/playwright/ttacart/'

Where baseURL comes from

.env BASE_URL= empty, so skipped TTA_ENV=qa picks the environment QA_BASE_URL=https://app.thetestingacademy.com result https://app.thetestingacademy.com
Resolved once when the config loads, not per test. Set BASE_URL to override, or pass a full https:// URL to goto() and baseURL is ignored completely.

Watch out: a leading slash resets to the origin

host only + /playwright/ttacart/ => https://host/playwright/ttacart/ host with a path + /inventory.html => https://host/inventory.html prefix dropped
Every page object uses a leading-slash PATH. That is harmless only because QA_BASE_URL is a bare origin. Point BASE_URL at something with a path segment and every page silently resolves to the wrong URL. Keep baseURL a bare origin.
